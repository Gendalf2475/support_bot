# Telegram-бот поддержки

Бот принимает обращения пользователей в личных сообщениях, проводит их через настраиваемую форму тикета и отправляет оформленный тикет в topic/forum thread группы поддержки. Один пользователь получает один topic, а тикетов у него может быть много: новый тикет создаётся после закрытия старого.

## Что нужно заранее

- Python 3.11 или новее.
- Telegram-группа поддержки с включёнными Topics/Forum.
- Токен бота от BotFather.

## Установка

```bash
cd support_bot
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`:

```env
BOT_TOKEN=токен_от_BotFather
SUPPORT_CHAT_ID=-1001234567890
DATABASE_URL=sqlite+aiosqlite:///data/majure_support_bot.db
LOG_LEVEL=INFO

TICKET_REMINDER_ENABLED=true
TICKET_REMINDER_AFTER_HOURS=24
TICKET_REMINDER_INTERVAL_MINUTES=60
TICKET_CHECK_INTERVAL_MINUTES=10

TICKET_AUTO_CLOSE_ENABLED=true
TICKET_AUTO_CLOSE_AFTER_DAYS=7
```

Боту нужны права читать и отправлять сообщения, создавать topic/forum thread и писать в них. Чтобы бот видел ответы поддержки, у BotFather отключите privacy mode через `/setprivacy` -> `Disable`.

## Миграции и запуск

```bash
alembic upgrade head
python -m app.bot.main
```

Миграции создают `users`, `message_maps`, `tickets`, `ticket_answers` и добавляют поля для причин закрытия, напоминаний, автозакрытия и пропущенных ответов.

## Как работает тикет

Пользователь отправляет `/start` в ЛС. Бот показывает приветствие и inline-кнопку `Открыть тикет`.

После нажатия бот показывает формы из `config/ticket_forms.yml`. Пользователь выбирает форму, отвечает на вопросы по очереди, проверяет итог и нажимает `Отправить`.

После отправки бот создаёт или использует существующий topic пользователя в группе поддержки и отправляет туда сообщение `🟣 Новый тикет` с данными формы. Под этим сообщением есть inline-кнопка `✅ Закрыть тикет`. Все прикреплённые пользователем медиа отправляются следом в тот же topic.

Пока тикет открыт, любые новые сообщения пользователя в ЛС копируются в этот topic. Ответы поддержки из topic копируются пользователю в ЛС. Если пользователь пишет `/start` при открытом тикете, бот сообщает, что тикет уже открыт.

После закрытия тикета пользователь может открыть новый. Topic при этом переиспользуется: один пользователь = один topic.

## Формы тикетов

Формы настраиваются в `config/ticket_forms.yml`. Если файл отсутствует или содержит ошибку YAML, бот не падает и использует встроенную fallback-форму `Другое`; ошибка пишется в лог.

Пример вопроса:

```yaml
questions:
  - id: "proof"
    text: "Прикрепите доказательства:"
    help_text: "Можно отправить скриншот, видео, документ или ссылку."
    required: true
    answer_type: "any"
```

Поля формы:

- `id` — уникальный технический ID формы.
- `title` — название формы для пользователя.
- `description` — описание формы.
- `button_text` — текст inline-кнопки.
- `admin_title` — заголовок тикета для поддержки.
- `questions` — список вопросов.

Поля вопроса:

- `id` — уникальный технический ID вопроса внутри формы.
- `text` — основной текст вопроса.
- `help_text` — необязательная подсказка, показывается под вопросом как `Подсказка: ...`.
- `required` — `true`, если вопрос обязательный; `false`, если его можно пропустить.
- `answer_type` — ожидаемый тип ответа: `text`, `media` или `any`.

`answer_type: text` принимает текст или caption у медиа. Если пользователь отправит медиа без текста/caption, бот попросит отправить текст.

`answer_type: media` принимает `photo`, `video`, `document`, `voice`, `audio`, `animation`, `sticker`. Если пользователь отправит только текст, бот попросит прикрепить файл, фото, видео или другое медиа.

`answer_type: any` принимает текст или поддерживаемое медиа. Если `answer_type` не указан, используется `any`.

Если `required: false`, под вопросом появляется inline-кнопка `Пропустить`. При пропуске бот сохраняет ответ с `skipped=true` и переходит к следующему вопросу.

## Команды поддержки

Команды работают только в `SUPPORT_CHAT_ID` и только внутри topic пользователя.

`/block`

Блокирует пользователя. Он не сможет открыть тикет, а его сообщения не будут пересылаться в поддержку.

`/unblock`

Разблокирует пользователя.

`/status`

Показывает `user_id`, `telegram_id`, `username`, `full_name`, `blocked`, `topic_id`, наличие открытого тикета, ID открытого тикета, статус тикета и дату создания тикета.

`/close`

Не закрывает тикет сразу. Бот показывает inline-кнопки с причинами закрытия:

- `✅ Решено`
- `👤 Нет ответа от пользователя`
- `🔁 Дубликат`
- `⛔ Нарушение правил`
- `📝 Другая причина`

После выбора причины бот закрывает тикет, сохраняет `close_reason`, заполняет `closed_at` и `closed_by_telegram_id`, пишет причину в topic и отправляет её пользователю.

## Закрытие кнопкой

Под первым сообщением нового тикета есть кнопка `✅ Закрыть тикет`. Она использует callback data:

```text
ticket_close:<ticket_id>
```

Нажатие показывает те же причины закрытия, что и `/close`. Выбор причины использует callback data:

```text
ticket_close_reason:<ticket_id>:resolved
ticket_close_reason:<ticket_id>:no_user_response
ticket_close_reason:<ticket_id>:duplicate
ticket_close_reason:<ticket_id>:rule_violation
ticket_close_reason:<ticket_id>:other
```

Кнопки работают только в группе поддержки, только внутри topic связанного тикета и только для открытого тикета. Повторное закрытие показывает alert `Тикет уже закрыт.`

## Напоминания

Если `TICKET_REMINDER_ENABLED=true`, бот периодически проверяет открытые тикеты. Интервал проверки задаёт `TICKET_CHECK_INTERVAL_MINUTES`.

Если тикет открыт дольше `TICKET_REMINDER_AFTER_HOURS`, бот отправляет в topic:

```text
⏰ Тикет открыт больше 24 часов.
Пожалуйста, проверьте обращение или закройте тикет, если вопрос решён.
```

Чтобы не спамить, повторное напоминание по тому же тикету отправляется не чаще, чем раз в `TICKET_REMINDER_INTERVAL_MINUTES`. Для этого бот хранит `last_reminded_at`.

Если напоминания не отправляются, проверьте `.env`, что scheduler включён, бот запущен после миграций, а у бота есть право писать в topic. Подробная ошибка будет в логах.

## Автозакрытие

Если `TICKET_AUTO_CLOSE_ENABLED=true`, бот закрывает `open` тикеты, где пользователь не писал дольше `TICKET_AUTO_CLOSE_AFTER_DAYS` дней. Считается именно последнее сообщение пользователя, поле `last_user_message_at`; ответы администрации его не обновляют.

При автозакрытии сохраняется `close_reason=auto_no_user_response`, `closed_by_telegram_id` остаётся пустым, бот пишет в topic причину и отправляет пользователю уведомление. Если уведомление пользователю не удалось отправить, тикет всё равно закрывается, ошибка пишется в лог и topic.

## Редактирование сообщений

Бот хранит связи копий сообщений в `message_maps`.

Если пользователь редактирует сообщение, бот пытается отредактировать уже отправленную копию в topic поддержки. Для текста используется `edit_message_text`, для caption медиа — `edit_message_caption`.

Если поддержка редактирует сообщение в topic, бот пытается отредактировать уже отправленную копию у пользователя.

Если Telegram не разрешает редактирование, тип сообщения изменился, сообщение слишком старое или связь не найдена, бот пишет fallback-уведомление и логирует ошибку.

## Частые проблемы

Если бот не создаёт topic, проверьте, что группа является форумом, бот добавлен администратором и имеет право создавать топики.

Если ответы поддержки не доходят пользователю, проверьте, что BotFather privacy mode отключён, бот находится именно в `SUPPORT_CHAT_ID`, а сотрудник пишет внутри связанного topic.

Если не работает редактирование сообщений, проверьте логи. Telegram разрешает боту редактировать только сообщения, которые отправил сам бот, и не позволяет превращать текст в медиа или один тип медиа в другой.
